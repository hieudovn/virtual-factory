## 3. DEFECT A — Reset/run generation stability

**Old failure mode:** after a reset the bridge kept the previous run's high
`last_sim_time`, so every subsequent poll (sim time still below the old high)
bumped the generation again → R1, R2, R3, R4, … for a single reset.

**New invariant:**

```python
if sim_time < last:        # reset detected
    generation += 1
    last_sim_time = sim_time   # re-baseline to the new run
else:
    last_sim_time = sim_time
```

One reset → exactly one generation transition. Verified evidence sequence:
`R1 → reset → R2 → R2 → R2 → R2 → R2 → R2 → reset → R3`.

**Tests:** A1 (`test_reset_generation_bumps_exactly_once`), A2 (second reset →
R3), A3 (`test_same_record_id_distinct_key_across_runs` — `QR-0001` in R1/R2
yields distinct idempotency keys because `run_id` changes once).

## 4. DEFECT B — Per-gateway delivery checkpoint

**Old failure mode:** a fact was marked projected as soon as ANY gateway
DELIVERED it; a second gateway that FAILED was never retried.

**New invariant:** delivery checkpoint is per
`(run_id, source_event_id, gateway_id)`:

```text
_delivered[run_id] = set[(source_event_id, gateway_id)]
```

- A gateway that already DELIVERED a fact is never re-sent (no duplicate).
- A gateway that FAILED is retried on the next poll.
- The outbound trace records one entry per successful (fact, gateway) delivery.

**Tests:** B1 (`test_failed_gateway_retried_other_not_duplicated`), B2 (after
both delivered → zero further deliveries), B3 (failure never mutates truth),
B4 (`test_single_gateway_backward_compatible`).

## 5. DEFECT C — Authoritative AP11 RELEASE occurrence time

**Old failure mode:** `release_time_s` used `runtime.simulation_time_s` at
poll/collection time, so a late bridge start reported a false (later) release
time.

**New invariant:** the release occurrence time is persisted on the WIP at the
moment of release — `AssyWipState.released_at_sim_s` — set in
`_execute_release_disposition` using the same timestamp convention as
`QualityRecord` (`simulation_time_s + station_elapsed`). The bridge reads
`ws.released_at_sim_s` (never poll time, never wall clock).

Evidence: actual release T=140s, late poll T+n=430s, emitted
`release_time_s = 140s`.

**Tests:** C1 (`test_release_time_is_occurrence_not_poll_time`), C2
(`test_qc_pass_and_release_are_distinct_facts`), C3
(`test_release_time_capture_consistent_with_runtime` — WIP timestamp equals
the AP11 RELEASE operation `completed_at_sim_s`).
