# 10 — Output Provenance Contract

Minimum machine-readable output envelope (frozen). Extends the existing
`SignalValue` / telemetry frame fields rather than replacing them.

## 10.1 Envelope fields (per emitted signal/frame)

```text
workspace_id        # stable logical VF workspace identity (NEW — threaded from manifest)
run_id              # per-run identity (existing: plant run generation)
scenario_id         # active scenario id (existing --scenario)
step                # integer step (existing)
simulation_time_s   # existing

runtime_signal_id   # VF-internal execution key (e.g. <workspace_id>.<asset>.<signal>)
                    #   distinct concept — NOT the PIM canonical id (B1)
canonical_signal_id # PIM-owned semantic identity, consumed READ-ONLY (B1)
value               # existing
unit                # existing

origin_kind         # "simulation" (fixed)
fidelity            # logical_only | synthetic_reference | first_order (NEW)
data_status         # synthetic | simulated_ground_truth (B6)

semantic_contract_version   # upstream semantic contract version (NEW)
semantic_contract_sha       # upstream semantic contract content hash (NEW)
evidence_note               # free-text provenance note (NEW)
```

## 10.2 Frozen rules

1. **PIM owns `canonical_signal_id` / `canonical_object_id` (B1).** VF consumes
   canonical ids read-only and MUST NOT invent or rewrite them. VF's internal
   execution key is a DISTINCT concept: `runtime_signal_id` (or `local_signal_id` /
   `model_signal_key`), never renamed to `canonical_signal_id`.
2. **Simulation output ≠ real plant data (B6).** `origin_kind` is always
   `simulation`; `data_status` is `synthetic` or `simulated_ground_truth`.
   Plain `measured` / `ground_truth` are NOT used for ordinary VF-generated data
   (they may be confused with real plant/site truth). Real plant data is a
   separate ingest pipeline, out of scope.
3. **Provenance is additive** — the existing `SignalValue` fields
   (`name, value, unit, category, quality, timestamp_s, source`) are preserved;
   workspace fields are added in the frame/envelope layer.
4. **`semantic_contract_version` + `semantic_contract_sha`** pin the upstream
   semantic contract the run consumed (see §12). With `semantic_binding.mode:
   required` (SH WTP), a missing/mismatched pin makes the workspace invalid.
   (An `unpinned` fallback MAY remain conceptually valid only for legacy/generic
   simulations with `mode: optional|none` — not for SH WTP.)

## 10.3 Where each field lives (current → future)

| Field | Today | Future (PH01+) |
|---|---|---|
| `workspace_id`, `fidelity`, `semantic_contract_*`, `evidence_note`, `origin_kind` | absent | add to `telemetry/telemetry_frame.py` frame dict + `observation/` envelope payload |
| `canonical_signal_id` | absent (PIM-owned) | consumed read-only from PIM artifacts; never generated by VF |
| `runtime_signal_id` | `SignalValue.name` (un-namespaced) | namespace-prefix at frame build (`SHW.` prefix) as a VF-internal key |
| `data_status` | `category`/`quality` | extend `OutputPolicy` categories (`synthetic`, `simulated_ground_truth`) |
| `scenario_id` | not stamped in frame | add to frame |

## 10.4 Non-goals

- No MES/PlantOS schema changes (that is a different contract).
- No change to `SignalValue` dataclass shape in PH00 — only the frame/envelope
  layer proposal is frozen.
