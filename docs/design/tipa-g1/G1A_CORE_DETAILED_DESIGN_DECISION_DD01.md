# G1A Core — SA Detailed Design Decision DD-01

**Decision:** `SA DESIGN-LOCK CANDIDATE`, 2026-10-31, grounded by roadmap/G1A architectural authority [#123](https://github.com/hieudovn/virtual-factory/issues/123). Detailed JSON Schemas in PR #132 are still under technical review until contract QA gate. **Not authorization to run PM G2A-01 (#127).**

## 1. Subsystem boundaries and ownership
Use existing `virtual_factory.discrete.FutureEventScheduler` as the reference scheduler, with an additive `FactoryCoordinator` rather than replacing `AssyLineRuntime`, Water Bottle or `discrete/`. Separate (i) module owned local operation state and private RNG, (ii) coordinator owned global time/events, (iii) ledger owned material inventory/reservation/transfer, (iv) consumer-owned MES/QMS/PlantOS records. Internal event ledger is not a substitute for material transfer authority or MES/QMS business decisions. F0/F1/F2/F3 modules all implement the same registration and clock contracts but may declare different capabilities.

**Execution modes** are immutable within one generation: Standalone uses explicit synthetic local input; Integrated forbids local regeneration of WIP. Adapter must raise a controlled compatibility error if required `ADVANCE_TO_EVENT_BOUNDARY` is unsupported; do not fabricate a uniform ASSY local clock.

## 2. Time, identity and numeric representation
- A FactoryRun header is immutable after initialization and includes `factory_run_id`, `generation`, `epoch_utc`, seed, workspace/definition+model revisions/digest, calendar and source provenance. Epoch must be offset-aware UTC.
- Runtime clock is `SimTick` **nonnegative integer microseconds since the pinned UTC epoch**; wire event time is exactly `epoch_utc + tick_us`. Legacy `simulation_time_s` floats are converted exactly once by an adapter using documented decimal rounding, rejecting NaN/inf/negative/past times and representation error greater than an agreed tolerance. Never tie-break by wall clock or thread completion.
- SA policy for authoritative material **quantities is base-10 decimal strings** (e.g. `"1"`, `"1.250"`). Parse as Decimal; reject exponent, NaN, signed negative and canonical collisions. `EA` is integral unless a definition explicitly permits fractional count (not in TIPA P0); KG/L and dimensional units use declared UOM precision. JSON Schema verifies syntax; semantic validator verifies strictly positive/nonzero, capacity, precision, dimensions, conversion and BOM/yield. Avoid binary floats for stock.
- `DefinitionProvenance` (PDF_EXPLICIT / VF_ACCEPTED_BASELINE / MES_AS_BUILT / SA_INFERENCE / SYNTHETIC_ASSUMPTION / PENDING_TIPA) records provenance of the modeled assumptions. `SourceKind` (`SIMULATED` vs `REPLAYED_SOURCE`) records origin of **the emitted event**. An event generated by a process described by the PDF is still SIMULATED, not a PDF source event. No live TIPA ingestion in P0 integrated factory without separate contract.
- IDs are run-generation-qualified and stable: `factory_run_id` + `generation` + `module_id` + module-local event sequence; motor number is an attribute, not a globally unique key. Map physical AA10 identities through versioned crosswalk; no inference based on string similarity.

## 3. Deterministic scheduler and proposal protocol

**Canonical serial reference algorithm (conceptual, not executable Python):**
```text
assert run.state == RUNNING
T = earliest eligible global scheduled SimTick
while still pending at T:
    snapshot = immutable committed shared state at T
    proposals = all eligible module events for T (possibly computed in parallel)
    check proposal purity and validity against snapshot + module manifest
    canonical_sort(proposals, priority_phase, stable_module_id, module_local_sequence, stable_event_id)
    for each proposal in canonical order:
        revalidate material/resource versions, prerequisites and idempotency
        if invalid: emit deterministic rejection/wait result; no shared mutation
        if valid: atomic commit event + resource/material legs + genealogy + outbox
        notify only affected module with commit receipt
    enqueue any deterministic events unlocked at T; evaluate until fixed point
    if zero-time budget exceeded: FAILED with no partial unreported write
advance to next T only after all causal commitments at T are resolved
```

**Event phases** are relative to causal dependencies, not merely alphabetical event names. First deliver committed resource/material receipts that are effective at T, then evaluate newly eligible operation starts, then operation completions and derived production under scheduler's causal graph; if completion itself enables next operation at same T, the fixed-point loop handles this. **Never let phase priority invert cause/effect**; rejected operation must not create child WIP, and a receipt at T may only unblock an operation at T under declared zero transfer latency.

**Stable tie-break** when *two consumers request the same WIP*: same time and phase → lexicographic stable module ID → module-local sequence → event ID, **then ledger version** determines one winner, one deterministic WAITING_FOR_MATERIAL. Reordering module registration/worker completion cannot change result.

**RNG:** derive independent module/entity streams deterministically via a stable cryptographic digest/HMAC of (run seed, module ID, scenario revision, entity ID, stream name). Do not share mutable process-wide RNG or use Python salted hash. Restoring a checkpoint restores per-stream counters/position. A predeclared scenario random seed is not sufficient proof of deterministic parallelism without this rule.

**Non-goals G2A-01:** real concurrent worker pool, distributed brokers, cross-host transactions, live MES/PlantOS writes, physical calibration models. First implement **serial deterministic reference**, parallel proposal optional only after event digest equality with serial oracle.

## 4. Material ledger transaction and operation boundary

A Material item has **separate orthogonal dimensions**: physical location (buffer/in-transit/in-process), reservation owner/version, eligibility (unknown/accepted/held/rejected), lifecycle (produced/consumed/scrapped). Do **not** encode all of these into one total-order enum. A physically present HOLD unit exists in inventory but cannot be reserved as qualified.

Unit/lot/batch contract:
- `MaterialUnit` has stable run-scoped identity and immutable creation causation.
- `MaterialLot` supports partial withdrawal with Decimal quantities; a WIP can be formed from one or several parent lots.
- `Buffer` has finite or declared unlimited capacity and allowed material types, and optionally fifo/priority dispatch.
- `Transfer` is idempotent `REQUESTED → SHIPPED → IN_TRANSIT → RECEIVED`, with rejected/cancelled paths and transport delay/capacity checks. If producer and consumer are co-located, transfer can complete at the same tick only under declared zero transport time.
- `Reservation` has operation owner, exact items/qty, eligible status revision and idempotency key; double reservation/consumption fails closed.
- `MaterialTransaction` includes one or more debit/credit legs and in-place transformations. For a join, atomic commit creates exactly one child, consumes all qualified parents according to declared BOM, and writes genealogy edges, event IDs and outbox in the same boundary. If an operation START consumes parents but completion later fails, the model keeps input as WIP in process and records scrap/rework/return; it never recreates input automatically.

**Ledger conservation equation (per material type with conversion recipe):**
```text
closing = opening + produced/received − shipped/consumed − scrapped ± explicit adjustment
```
This is applied to each owned stock/location with proper transfer counterparty, **not** across different material types (e.g. one rotor + one stator → one motor requires BOM conversion, not naive sum=conservation).

Atomicity/idempotency:
- Transaction id, scoped idempotency key and payload digest checked together. Retrying the same id+digest returns original receipt; same key/different digest is a hard conflict.
- Version-checked reservation and capacity across all input buffers, child creation, genealogy, committed event and outbox. No transfer receive or material production from an uncommitted MQTT event.
- Restart/replay at any reservation/ship/receipt/consume boundary must preserve stock, genealogy and outbox cursor; if in-memory P0 reference cannot show crash-safe atomic recovery, gate is `NOT READY`, not assumed by deterministic in-memory unit tests.
- Missing/input ineligible → `WAITING_FOR_MATERIAL` / `WAITING_FOR_QUALITY` according to cause, not equipment fault. Quality observation is evidence; operative hold requires explicit policy and approved authority.

## 5. Checkpoints and projections
A consistent checkpoint is `(factory clock, pending future events, module states and per-module RNG, material ledger version/state, resource reservations, event ledger sequence, committed outbox cursor)`. It must be taken at a committed safe boundary, with config+model digests pinned and a single replay policy.

Projection is after durable commit; at-least-once delivery with `source_system+source_event_id+destination+contract_version` idempotency scope. Transport `received_at` is not simulation event-time. Consumer mappings C1/C2/C2b/C3/C4/C5 need #129 audit and MES/QMS/PlantOS SA sign-off. A produced Motor with AP11 Completed is not automatically Good/QualityReleased; `record_only` hold cannot be treated as an operative hold without explicit policy.

## 6. Design-to-implementation breakpoints
- **SA can lock G1A Core orchestration semantic rules (this ADR)**. PM #127 still **BLOCKED** until #131 governance merges, PR #132 docs accepted, exact fixtures/contract checks pass and a new pinned task JSON is issued.
- **G1A Material schema still needs QA** for transfer, Decimal precision, all-or-nothing join, persistence boundary. PM #128 remains blocked after #127 acceptance.
- **ASSY coupling remains DRAFT** until #126 shows actual external-feed suppression and safe global time seam. Old ASSY standalone and Water Bottle are regression baselines.
- **G1B/C remains DRAFT** until #129 and cross-SA authority/identity/UX decisions.

## 7. Required PM evidence before authorizing G2A
A separate read-only/contract-check gate must run JSON Schema draft 2020-12 validation and semantic negative fixtures for bad ids, nonpositive/EA fractional quantities, invalid SHIP/RECEIVE order, duplicate WIP, same-time contention, wrong UTC offset, stale calibration and unqualified/unknown Quality state; provide a deterministic oracle specification. Fixtures T01/T02 are **examples only**, not verified test traces; their all-zero SHA digest is a placeholder and MUST be replaced with computed digest before live execution.
